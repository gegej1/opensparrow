# 多平台统一仓方案（OpenSparrow 根目录版）

## 结论先说

- 统一真源仓继续成立。
- 不再以 `openclawNative/` 或 `opensparrow_win/` 单独承载真源。
- 从本次起，`/Users/eduardogan/Desktop/GHJProject/opensparrow` 作为统一工作根。
- 平台入口不强行统一；共享逻辑、配置契约、验证链、构建/导出规则、容器基线统一。

## 为什么改成 `opensparrow/` 根目录

1. 它天然包住了所有历史快照、push copy、实验目录，边界冻结与归档更顺手。
2. 它当前尚未初始化 git，可以在第一次提交前就把 `.gitattributes` / `.gitignore` 规则定干净。
3. 它能同时容纳 `openclawNative` 迁入的多平台 runtime/source 和 `opensparrow_win/feishu-source` 迁入的 USB/Feishu 真源。
4. 后续容器化、导出和归档动作都可以在一个根目录内完成，不再跨两个顶层工作目录跳转。

## 风险结论

结合已有风险评估、深潜调研和迁移矩阵，当前没有“不可控阻断风险”。

### 完全可控

- CRLF/LF 漂移
- 可执行权限位丢失
- 二进制误判文本
- PowerShell/Bash 共存
- CI 矩阵差异
- 路径分隔符差异
- Docker bind mount 性能
- Docker UID/GID 映射
- npm 平台二进制
- USB 文件名限制
- USB 权限位丢失

### 部分可控

- Docker host networking 在 Mac/Windows 上受限
- Windows `MAX_PATH` 路径长度
- exFAT 无日志
- Docker Synchronized File Shares 平台不对称

### 仍需坚持的原则

- 统一仓库 ≠ 统一入口脚本
- 不把平台 wrapper 粗暴合并成一份脚本
- 不在历史快照和 generated output 上继续手改
