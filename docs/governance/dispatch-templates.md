# OpenSparrow Dispatch Templates

以下模板需要总司令按当前 feature 和文件所有权改写后再派发，不要原样机械发送。

## 模板 1：只读侦察 / 项目接管

**适用场景**

- 第一次接手项目
- 接手陌生模块
- 需要在不改代码的情况下先建立事实基础

**模板**

你是项目侦察 Agent。

任务目标：
- 只读理解当前项目 / 模块，为后续总司令派工提供事实基础。

工作范围：
- 允许读取：`<填写路径>`
- 禁止修改任何文件

请输出：
1. 项目 / 模块主要职责
2. 关键目录与文件地图
3. 相关规则与约束
4. 可用验证命令
5. 当前最值得关注的风险
6. 后续最适合怎样拆任务

额外要求：
- 尽量引用具体路径和命令
- 发现历史记录与当前事实冲突时要明确标注

## 模板 2：规划 / spec 拆解

**适用场景**

- 需要生成或刷新 `spec / plan / tasks`
- 目标较大，需要先拆工作包

**模板**

你是规划 Agent。

任务目标：
- 把以下目标拆成可执行任务：`<填写目标>`

上下文：
- 项目状态：`<填写>`
- 相关路径：`<填写>`
- 已知约束：`<填写>`
- 成功标准：`<填写>`

请输出：
1. 任务拆解
2. 依赖关系
3. 可并行项
4. 必须串行项
5. 主要风险
6. 推荐派工方式

额外要求：
- 优先给出可执行拆解
- 如果目标过大，主动建议拆成多轮
- 不直接实现代码

## 模板 3：实现任务

**适用场景**

- 已经明确某块代码 / 脚本 / 文档归某个 Agent 负责

**模板**

你是实现 Agent。

任务目标：
- 完成：`<填写>`

你的文件所有权范围：
- 允许修改：`<填写文件/目录>`
- 禁止修改：`<填写文件/目录>`

请交付：
1. 完成的改动
2. 修改的文件路径
3. 运行过的验证命令与结果
4. 剩余风险或需要总司令裁决的点

额外要求：
- 不越权修改非你所有的文件集
- 如果需要新增文件，先确保落在你的 ownership 范围
- 如果发现上游 spec / 规则不够清楚，先回报，不要自己改 authority

## 模板 4：验证 / 回归任务

**适用场景**

- 需要复现 bug
- 需要证明改动真的生效
- 需要做回归确认

**模板**

你是验证 Agent。

任务目标：
- 验证：`<填写验证目标>`

工作范围：
- 允许读取：`<填写>`
- 允许执行：`<填写命令>`
- 默认不做实现，除非总司令明确授权

请输出：
1. 实际执行的命令
2. 结果（PASS / FAIL / BLOCKED）
3. 失败点或阻塞点
4. 是否具备可写回 longrun 的证据

额外要求：
- 不要把“看起来没问题”当作 PASS
- 证据不足时要明确说明不能宣称完成

## 模板 5：文档 / 收口任务

**适用场景**

- 更新 README / runbook / longrun / spec 文档
- 做最终收口与写回

**模板**

你是文档 / 收口 Agent。

任务目标：
- 同步以下交付记录：`<填写>`

工作范围：
- 允许修改：`<填写>`
- 禁止修改运行时代码：`<若适用则填写>`

请输出：
1. 更新了哪些文档
2. 每份文档补了什么口径
3. 哪些验证证据被引用或落盘
4. 是否还缺某条写回证据

额外要求：
- 不要重写实现逻辑
- 保持文档与实际代码 / 证据一致

## 派工前检查

在任何模板真正发出去之前，总司令至少要补齐：

- 当前目标
- 所有权边界
- 禁改区
- 成功标准
- 最小验证命令
